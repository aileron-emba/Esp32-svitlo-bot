# 💡 ESP32 Світло-бот

ESP32 стоїть у розетці і раз на 30 секунд шле пінг на сервер.
Сервер повідомляє в Telegram:

- 🔴 **Світло зникло о 14:05** — пінги припинились (ESP32 знеструмилась);
- 💡 **Світло з'явилось о 18:30, не було 4 год 25 хв** — пінги відновились.

```
 [ESP32 у розетці] --Wi-Fi--> [роутер] --інтернет--> [сервер] ---> [Telegram]
        пінг кожні 30 с                     нема пінгів 90 с = нема світла
```

> **Чому потрібен сервер?** Коли зникає світло, ESP32 вимикається і сама
> нічого надіслати не може. Тому «світла нема» визначає сервер — за відсутністю пінгів.
> Токен бота через це живе на сервері (`server/.env`), а в прошивку вшиті адреса сервера
> і ключ `API_KEY`.

> ⚠️ Роутер теж має бути без ДБЖ (або живитися від тієї ж лінії), інакше зникнення
> інтернету теж виглядатиме як «нема світла».

## 1. Telegram-бот

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримаєте **токен**.
2. Після запуску сервера напишіть своєму боту `/start` — він відповість вашим **chat ID**.
   Для групи: додайте бота в групу і напишіть там `/start` (chat ID групи починається з `-`).
3. `/status` — поточний стан світла.

## 2. Сервер

Потрібен комп'ютер з постійним живленням і доступом з інтернету:
VPS, або Raspberry Pi **в іншому місці** (не там, де вимикають світло).
Тільки Python 3.9+, без залежностей.

```bash
cd server
cp .env.example .env    # впишіть BOT_TOKEN і придумайте API_KEY
python3 svitlo_server.py
```

Перевірка: `curl http://IP_СЕРВЕРА:8080/health` → `{"ok": true}`.

Автозапуск через systemd (Linux / Raspberry Pi):

```bash
sudo useradd -r svitlo
sudo mkdir -p /opt/svitlo && sudo cp -r server /opt/svitlo/
sudo chown -R svitlo /opt/svitlo
sudo cp server/svitlo.service /etc/systemd/system/
sudo systemctl enable --now svitlo
journalctl -u svitlo -f
```

Порт 8080 має бути відкритий у фаєрволі. Можна поставити за nginx/Caddy з HTTPS —
ESP32 підтримує `https://` адреси.

## 3. Прошивка ESP32

1. Відкрийте `firmware/include/config.h` і вкажіть:
   - `SERVER_URL` — адреса сервера, напр. `http://203.0.113.10:8080`;
   - `API_KEY` — той самий, що в `server/.env`.
2. Прошийте через [PlatformIO](https://platformio.org/) (VS Code → PlatformIO → Upload)
   або з терміналу:
   ```bash
   cd firmware
   pio run -t upload
   pio device monitor     # лог, 115200
   ```

## 4. Налаштування пристрою

1. Увімкніть ESP32. З'явиться Wi-Fi мережа **`Svitlo-Setup`** (пароль `svitlo123`).
2. Підключіться телефоном — сторінка налаштувань відкриється сама
   (або відкрийте http://192.168.4.1).
3. Виберіть свою Wi-Fi мережу, введіть пароль, **chat ID** і назву («Дім», «Дача»…).
4. «Зберегти» — пристрій перезавантажиться, і бот напише
   «✅ Пристрій підключено».

Пізніше налаштування доступні в домашній мережі: **http://svitlo.local**
(або за IP пристрою). Там же кнопка «Надіслати тестове повідомлення».

### Поведінка

| Ситуація | Що робить ESP32 |
|---|---|
| Немає налаштувань | Піднімає `Svitlo-Setup` |
| Роутер не з'явився за 20 с після старту | Піднімає `Svitlo-Setup`, але продовжує пробувати підключитися; щойно підключилась — вимикає точку доступу |
| Wi-Fi зник більше ніж на 3 хв | Піднімає `Svitlo-Setup` (щоб можна було змінити мережу) |
| Кнопка **BOOT** затиснута 5 с | Стирає налаштування |

Світлодіод (GPIO2): блимає — режим налаштування; світить — пінги проходять; не світить — проблема з Wi-Fi/сервером.

Усі параметри (інтервал пінгу, піни, назва точки доступу) — у `firmware/include/config.h`.
Таймаут «нема світла» — `OFFLINE_TIMEOUT` у `server/.env` (має бути більшим за 2–3 інтервали пінгу).

## API сервера

`POST /api/ping` і `POST /api/test`, JSON:

```json
{"key": "API_KEY", "device_id": "esp32-…", "chat_id": "123456789", "name": "Дім", "uptime": 42, "rssi": -60}
```

Одним сервером і ботом можна обслуговувати багато пристроїв і чатів.
